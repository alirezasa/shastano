# سکوی نوآوری و فناوری شستان — بررسی قالب و سناریوی پیاده‌سازی در SharePoint Server 2019 (On-Premises)

> این سند مرحله‌ی اول است: بررسی قالب فعلی (`index.html`) و سناریوی کامل پیاده‌سازی.
> پیاده‌سازی مستر پیج، لیست‌ها و کدها در مراحل بعد، بر اساس تصمیم‌های بخش «سؤالات باز» انجام می‌شود.

---

## ۱. بررسی قالب فعلی

قالب یک SPA تک‌فایلی است (Tailwind CDN + FontAwesome + داده‌های ساختگی در JS) با ۷ «صفحه»:
خانه، دایرکتوری شرکت‌ها، صفحه‌ی شرکت، نظام مسائل (RFP)، کارتابل هلدینگ، تماس با ما، صفحه‌ی عمومی.
سوئیچ نقش کاربر (عمومی / شرکت / هلدینگ) صرفاً نمایشی است.

### ۱-۲. کمبودهای کارکردی (برای یک سکوی حرفه‌ای)

- **پنل شرکت تابعه وجود ندارد** — فقط یک مودال «ثبت مسئله» هست. شرکت باید داشبورد داشته باشد: پیش‌نویس‌ها، در انتظار بررسی، برگشت‌خورده‌ها (با نظر کارشناس)، منتشرشده‌ها، ویرایش پروفایل شرکت، ثبت R&D/محصول/…
- **کارتابل هلدینگ** فقط RFP دارد؛ باید برای همه‌ی انواع محتوا (پروفایل شرکت، R&D، محصولات، قراردادها…) باشد، با مشاهده‌ی جزئیات، مقایسه‌ی نسخه‌ی قبلی/جدید، نظر، تاریخچه، گزارش و خروجی Excel.
- **صفحه‌ی جزئیات RFP** وجود ندارد (دکمه فقط Toast نشان می‌دهد) و مسیر «ارسال پیشنهاد» توسط شرکت‌های دانش‌بنیان تعریف نشده.
- **ورود/خروج واقعی**، نمایش نام کاربر و شرکت، جستجوی سراسری، اخبار و رویدادها، پرسش‌های متداول، راهنمای فرایند.

## ۲. تصمیم معماری

### ۲-۱. چرا «سایت کلاسیک Publishing» و نه Modern
در SharePoint 2019 تجربه‌ی Modern **مستر پیج سفارشی را نمی‌پذیرد** و برای دسترسی ناشناس (Anonymous) طراحی نشده است.
بنابراین:

- **Site Collection** با قالب *Publishing Portal* (یا Team Site + فعال‌سازی Publishing Infrastructure)، زبان **فارسی (1065)** تا RTL، تقویم شمسی و منوهای سیستم فارسی باشند.
- **مستر پیج سفارشی** (`shastan.master`) — بر پایه‌ی `seattle.master` با حفظ تمام ContentPlaceHolder های الزامی.
- **Page Layout** ها برای صفحات محتوایی (اخبار، صفحه‌ی ثابت).
- بخش‌های پویا (لیست شرکت‌ها، RFP ها، پنل‌ها) به صورت **ماژول‌های JS** که با REST API شیرپوینت (`/_api`) کار می‌کنند و در صفحات جایگذاری می‌شوند.
- **MDS** (Minimal Download Strategy) غیرفعال.

### ۲-۲. ساختار سایت و Zone ها

```
https://innovation.shastan.ir            ← Zone: Internet  (Anonymous + FBA/ADFS برای ورود)
https://innovation.shastan.local         ← Zone: Default   (Windows Auth — برای Crawl جستجو)

/ (Site Collection ریشه — عمومی، Anonymous: Lists and Libraries)
 ├─ Pages/                  صفحات عمومی (خانه، شرکت‌ها، RFP، …)
 ├─ Lists/                  همه‌ی لیست‌های داده (بخش ۴)
 ├─ SiteAssets/shastan/     CSS/JS/فونت/تصاویر قالب
 └─ /panel  (Subsite — ارث‌بری قطع، Anonymous خاموش)
      ├─ Pages/company.aspx  پنل شرکت تابعه
      └─ Pages/admin.aspx    کارتابل و مدیریت هلدینگ
```

قرار دادن پنل‌ها در Subsite بدون دسترسی ناشناس باعث می‌شود ورود به پنل **خودکار** صفحه‌ی لاگین را باز کند و هیچ صفحه‌ی مدیریتی به کاربر ناشناس نشت نکند. داده‌ها در ریشه هستند و پنل‌ها با `/_api/web` سایت ریشه کار می‌کنند.

### ۲-۳. قاعده‌ی طلایی امنیت
> **پنهان کردن دکمه در UI امنیت نیست.** تمام محدودیت‌ها باید با مجوزهای خود شیرپوینت اعمال شوند؛ UI فقط بر اساس همان مجوزها شکل می‌گیرد.

## ۳. نقش‌ها و مجوزها

### ۳-۱. گروه‌های شیرپوینت

| گروه | اعضا | سطح دسترسی |
|------|------|------------|
| `Anonymous` (کاربر ناشناس) | همه | View Items فقط روی لیست‌های عمومی؛ Add Items روی «پیام‌های تماس» (و در صورت تصمیم، «پیشنهادها») |
| `SHN-Visitors` | همه‌ی کاربران احراز هویت‌شده | Read |
| `SHN-Company-<کد>-Editors` (یک گروه برای هر شرکت، ۲۸ گروه) | کارشناسان هر شرکت تابعه | سطح سفارشی **«ویرایش بدون حذف»** (Contribute منهای Delete) فقط روی پوشه/آیتم همان شرکت |
| `SHN-Company-<کد>-Managers` *(اختیاری)* | مدیر هر شرکت | تأیید داخلی شرکت قبل از ارسال به هلدینگ |
| `SHN-Holding-Reviewers` | کارشناسان هلدینگ | Approve روی لیست‌های داده |
| `SHN-Holding-Admins` | مدیران سامانه | Approve + Manage Lists + مدیریت اطلاعات پایه |
| `SHN-Owners` | تیم IT | Full Control |

### ۳-۲. جداسازی داده‌ی شرکت‌ها (مهم‌ترین بخش امنیتی)

ترکیب سه قابلیت بومی شیرپوینت:

1. **Content Approval** روی همه‌ی لیست‌های داده (Require content approval = Yes) + **Versioning**.
   → کاربر ناشناس و بقیه فقط **آخرین نسخه‌ی تأییدشده** را می‌بینند. شرکت نمی‌تواند خودش چیزی را منتشر کند چون تغییر `_ModerationStatus` فقط با مجوز Approve ممکن است — حتی اگر مستقیماً REST صدا بزند.
2. **Draft Item Security = «Only users who can edit items»**
   → پیش‌نویس‌ها و موارد در انتظار فقط برای کسانی که حق ویرایش دارند (همان شرکت + هلدینگ) دیده می‌شوند.
3. **یک پوشه برای هر شرکت** در هر لیست با مجوز اختصاصی (۲۸ پوشه → بدون مشکل مقیاس‌پذیری Unique Scope):
   - `Anonymous/Visitors`: Read (ارث‌بری کپی‌شده)
   - `SHN-Company-<کد>-Editors`: ویرایش بدون حذف
   - `SHN-Holding-*`: Approve
   → شرکت الف حتی پیش‌نویس‌های شرکت ب را نمی‌بیند و نمی‌تواند چیزی در پوشه‌ی دیگری ثبت کند.

برای لیست **شرکت‌ها** (هر شرکت یک آیتم) به‌جای پوشه، روی خود آیتم مجوز اختصاصی تنظیم می‌شود.

## ۴. طراحی لیست‌ها

> نام داخلی (Internal Name) ستون‌ها **انگلیسی** و بدون فاصله ساخته می‌شوند، سپس عنوان نمایشی فارسی می‌شود؛ این کار REST و CAML را ساده و پایدار می‌کند.

### ۴-۱. اطلاعات پایه (فقط مدیر هلدینگ)

**`TechDomains` — حوزه‌های ۷گانه**
`Title`، `DomainKey`، `Icon` (نام آیکن)، `Color`، `Description`، `SortOrder`، `IsActive`

**`CompanyCategories` — دسته‌بندی شرکت‌ها**
`Title` (پتروشیمی، نفت و قیر، روانکار، …)، `SortOrder`

**`SiteSettings` — تنظیمات صفحه‌ی اول**
`Title`(کلید)، `Value`، `Value2` — متن Hero، تصویر Hero، اطلاعات تماس فوتر، شبکه‌های اجتماعی و …

**`NavigationLinks` — منوی اصلی و فوتر**
`Title`، `Url`، `Location` (Header/Footer1/Footer2)، `ParentLink` (Lookup)، `Icon`، `SortOrder`، `Audience` (All/Authenticated/Company/Holding)

### ۴-۴. عملیاتی

**`AuditLog` — لاگ عملیات** (فقط هلدینگ)
`ListName`، `ItemId`، `ItemTitle`، `Company`، `Action` (ثبت/ارسال/تأیید/برگشت/رد/بایگانی)، `Actor`، `Comment`، `ActionDate`

**`Statistics` — آمار صفحه‌ی اول** (به‌روزرسانی خودکار یا دستی)
`Title`، `Count`، `Icon`، `Color`، `TargetUrl`، `SortOrder`

### ۴-۵. ایندکس‌ها و کارایی
- ایندکس روی `Company`، `Domain`، `WorkflowStatus`، `CallStatus`، `Created`.
- همه‌ی Query ها با `$select`، `$top` و صفحه‌بندی (`$skiptoken`)؛ آستانه‌ی ۵۰۰۰ آیتم رعایت شود.
- BlobCache برای فایل‌های قالب فعال شود.

## ۵. گردش‌کار (سناریوی اصلی)

### ۵-۱. چرخه‌ی تأیید (`WorkflowStatus`) — برای همه‌ی انواع محتوا

```
                  ┌──────────── ویرایش توسط شرکت ─────────────┐
                  ▼                                           │
 [پیش‌نویس] ──ارسال──► [در انتظار بررسی هلدینگ] ──تأیید──► [منتشرشده]
     ▲                     │            │                     │
     │                  برگشت          رد نهایی           بایگانی (هلدینگ)
     │                     ▼            ▼                     ▼
     └───اصلاح─── [برگشت جهت اصلاح]  [رد شده]            [بایگانی]
```

| وضعیت | `_ModerationStatus` بومی | چه کسی می‌بیند |
|-------|-------------------------|---------------|
| پیش‌نویس | Pending (2) | شرکت + هلدینگ |
| در انتظار بررسی | Pending (2) | شرکت + هلدینگ |
| برگشت جهت اصلاح | Rejected (1) | شرکت + هلدینگ |
| رد شده | Rejected (1) | شرکت + هلدینگ |
| منتشرشده | Approved (0) | **همه، از جمله ناشناس** |
| بایگانی | Approved + `IsArchived` | فقط در آرشیو |

نکات:
- **ویرایش محتوای منتشرشده**: وقتی شرکت آیتم منتشرشده را ویرایش کند، آیتم به Pending می‌رود ولی **نسخه‌ی قبلیِ تأییدشده همچنان عمومی نمایش داده می‌شود** تا هلدینگ نسخه‌ی جدید را تأیید کند. در کارتابل، تفاوت نسخه‌ی قبلی و جدید (از Version History) نمایش داده می‌شود.
- «برگشت» و «رد» **دلیل اجباری** دارند که در `ReviewComments` (Append) و `AuditLog` ثبت می‌شود.
- اختیاری: مرحله‌ی **تأیید داخلی مدیر شرکت** قبل از ارسال به هلدینگ.
- اختیاری: تأیید دومرحله‌ای در هلدینگ (کارشناس → مدیر).

### ۵-۲. چرخه‌ی عمر فراخوان (`CallStatus`) — فقط پس از انتشار RFP

`فراخوان فعال` → `در حال ارزیابی پیشنهادها` → `منجر به قرارداد` (ایجاد آیتم در Contracts) / `بسته شده بدون نتیجه`
با رسیدن `Deadline`، کارت‌ها به‌صورت خودکار «مهلت به پایان رسیده» نشان داده می‌شوند.

### ۵-۳. سناریوهای کاربری

**الف) کاربر عمومی (ناشناس)**
1. وارد صفحه‌ی اول می‌شود: Hero، آمار زنده، ۷ حوزه، آخرین فراخوان‌ها، اخبار، لوگوی شرکت‌ها.
2. در «نظام مسائل» با جستجو و فیلتر (حوزه، شرکت، اولویت، وضعیت، مهلت) می‌گردد و وارد صفحه‌ی جزئیات `rfp.aspx?id=42` می‌شود (لینک قابل اشتراک و قابل ایندکس).
3. دایرکتوری شرکت‌ها → صفحه‌ی شرکت `company.aspx?id=5` با تب‌های: درباره، مسائل، R&D، محصولات، تماس.
4. ارسال پیشنهاد برای RFP و ارسال پیام تماس (با کپچا).
5. هرگز ریبون، منوی شیرپوینت، فرم‌های `DispForm/NewForm` یا صفحات `_layouts` را نمی‌بیند (Lockdown Mode فعال).

**ب) کاربر شرکت تابعه**
1. روی «ورود» کلیک می‌کند → صفحه‌ی ورود (هماهنگ با قالب) → بازگشت به **پنل شرکت**.
2. سامانه از روی عضویت گروه `SHN-Company-005-Editors` شرکت او را تشخیص می‌دهد؛ نام شرکت در هدر نمایش داده می‌شود.
3. داشبورد: کارت‌های «پیش‌نویس / در انتظار / برگشت‌خورده / منتشرشده» + اعلان‌ها.
4. ثبت مسئله‌ی جدید (فرم چندمرحله‌ای، ذخیره‌ی پیش‌نویس، پیوست، پیش‌نمایش) → «ارسال برای بررسی».
5. دریافت ایمیل/اعلان هنگام تأیید یا برگشت؛ اصلاح بر اساس نظر کارشناس و ارسال مجدد.
6. ویرایش پروفایل شرکت، ثبت R&D، محصول، قرارداد، اختراع و … — همه با همان گردش‌کار.
7. در صورت فعال بودن: مشاهده‌ی پیشنهادهای رسیده برای RFP های خودش.

**ج) کاربر هلدینگ**
1. ورود → **کارتابل** با شمارنده‌ی زنده، تب برای هر نوع محتوا، فیلتر شرکت/حوزه/تاریخ.
2. باز کردن هر درخواست در پنل کناری: جزئیات کامل، پیوست‌ها، تاریخچه‌ی نظرات، **مقایسه با نسخه‌ی منتشرشده‌ی قبلی**.
3. «تأیید و انتشار» / «برگشت جهت اصلاح» (دلیل اجباری) / «رد نهایی» (دلیل اجباری)؛ عملیات گروهی.
4. مدیریت: شرکت‌ها، حوزه‌ها، منو، تنظیمات صفحه‌ی اول، بایگانی، ارزیابی پیشنهادها، پیام‌های تماس.
5. گزارش‌ها: تعداد مسائل به تفکیک حوزه/شرکت/وضعیت، میانگین زمان بررسی، نرخ تبدیل RFP به قرارداد، خروجی Excel.

### ۵-۴. اعلان‌ها
| رویداد | گیرنده |
|--------|--------|
| ارسال برای بررسی | گروه کارشناسان هلدینگ |
| تأیید / برگشت / رد | ثبت‌کننده + گروه شرکت |

### ۶-۳. نکات فنی قالب در شیرپوینت
- Tailwind: `prefix: 'tw-'`، `corePlugins.preflight: false`، `important: '#shastan-app'` → بدون تداخل با کلاس‌هایی مثل `.hidden`، `.ms-*` و CSS هسته‌ی شیرپوینت.
- همه‌ی فایل‌ها محلی (بدون CDN) در `Style Library/shastan/` یا `_catalogs/masterpage/shastan/`.
- فونت Dana با `woff2` + `woff`، وزن‌های 400/500/700/900.
- اسکریپت‌ها: ماژول‌های ES بدون وابستگی سنگین (یا Vue 3 به‌صورت bundle) — ساخت با Vite؛ خروجی یک `shastan.js` + تقسیم بر اساس صفحه.
- escape همه‌ی خروجی‌ها و sanitize فیلدهای Rich Text (DOMPurify).
- تاریخ شمسی: `Intl.DateTimeFormat('fa-IR-u-ca-persian')` و ارقام فارسی.
- `X-RequestDigest` برای POST ها؛ مدیریت خطا و Loading/Skeleton.
- Lockdown Mode فعال بماند؛ صفحات عمومی فقط از طریق صفحات سفارشی داده نمایش دهند.

## ۷. زیرساخت و استقرار (چک‌لیست)

1. Web Application با دو Zone (Default: Windows برای Crawl؛ Internet: Anonymous + روش ورود انتخابی)، **HTTPS**، AAM.
2. نصب **Language Pack فارسی** و ساخت Site Collection با LCID 1065.
3. فعال‌سازی Publishing؛ غیرفعال‌سازی MDS؛ فعال نگه داشتن **Limited-access user permission lockdown mode**.
4. Anonymous Access روی سایت ریشه: «Lists and libraries» و فعال کردن فقط روی لیست‌های عمومی.
5. اجازه‌ی خواندن لیست از REST برای ناشناس (در SP 2013+ به‌صورت پیش‌فرض مسدود است):
   ```powershell
   $wa = Get-SPWebApplication https://innovation.shastan.ir
   $wa.ClientCallableSettings.AnonymousRestrictedTypes.Remove([Microsoft.SharePoint.SPList], "GetItems")
   $wa.Update()
   ```
   (پس از آن در محیط تست بررسی شود؛ در صورت محدودیت، نمایش عمومی از مسیر Search انجام می‌شود.)
6. پیکربندی Search برای Anonymous (نتایج Security Trimmed هستند و فقط نسخه‌ی منتشرشده ایندکس می‌شود).
7. BlobCache، فشرده‌سازی IIS، Output Cache برای صفحات عمومی.
8. اسکریپت PowerShell/PnP برای **ساخت خودکار** همه‌ی Site Column ها، Content Type ها، لیست‌ها، پوشه‌ها، گروه‌ها و مجوزها (قابل تکرار روی Test و Production).
9. محیط Test جدا از Production.

## ۸. سؤالات باز (قبل از پیاده‌سازی)

1. **احراز هویت کاربران شرکت‌های تابعه**: حساب AD در دامین هلدینگ دارند؟ یا باید **FBA** (نام کاربری/رمز در دیتابیس SQL با صفحه‌ی ورود سفارشی) راه‌اندازی شود؟ یا ADFS موجود است؟
2. **سایت روی اینترنت منتشر می‌شود یا فقط اینترانت؟** (روی تنظیمات Zone، HTTPS، کپچا و سخت‌سازی اثر مستقیم دارد.)
3. **Workflow Manager** روی فارم نصب است؟ اجازه‌ی نصب **Farm Solution** (کد سمت سرور C#: Event Receiver برای تولید کد، اعتبارسنجی، ایمیل و لاگ) داریم؟ اگر نه، همه‌چیز سمت کلاینت (REST + `SP.Utilities.Utility.SendEmail`) پیاده می‌شود.
4. **ارسال پیشنهاد** توسط شرکت‌های دانش‌بنیان: بدون ثبت‌نام (فرم ناشناس + کپچا) یا با ثبت‌نام (نوع کاربر چهارم)؟
5. اطلاعات **نماینده‌ی فناوری** شرکت‌ها عمومی باشد یا فقط برای کاربران واردشده؟
6. تأیید داخلی مدیر شرکت قبل از هلدینگ و/یا تأیید دومرحله‌ای در هلدینگ لازم است؟
7. لوگو، رنگ‌های سازمانی و نام نهایی برند (شستان) — فایل لوگو ارسال شود.
8. نسخه و آخرین CU نصب‌شده روی SharePoint 2019.

> ⚠️ **نکته‌ی مهم پشتیبانی**: پشتیبانی تمدیدشده‌ی SharePoint Server 2019 در **۱۴ ژوئیه‌ی ۲۰۲۶** به پایان رسیده و دیگر به‌روزرسانی امنیتی دریافت نمی‌کند. برای سایتی که **روی اینترنت و با دسترسی ناشناس** منتشر می‌شود این ریسک جدی است (WAF/Reverse Proxy جلوی سرور، سخت‌سازی و برنامه‌ی مهاجرت به SharePoint Server Subscription Edition توصیه می‌شود). معماری این سند (Classic Publishing + REST) بدون تغییر روی Subscription Edition هم قابل اجراست.
