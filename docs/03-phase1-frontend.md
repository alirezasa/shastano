## اجرا

```bash
npm install
npm run build      # خروجی در dist/
npm run serve      # http://localhost:8080
```

در حالت نمایشی (بدون شیرپوینت) داده‌ها در `localStorage` مرورگر ذخیره می‌شوند و نوار «حالت نمایشی» پایین صفحه امکان تغییر نقش (عمومی / شرکت / هلدینگ) و بازگردانی داده‌ها را می‌دهد.
در صفحه‌ی ورود نمایشی: نام کاربری `company` یا `holding` با هر رمزی.

**سناریوی تست کامل:** ورود با `company` → ثبت مسئله‌ی جدید → ارسال → تغییر نقش به هلدینگ → کارتابل → برگشت جهت اصلاح با دلیل → نقش شرکت → اصلاح و ارسال مجدد → نقش هلدینگ → تأیید و انتشار → نقش عمومی → مسئله در نظام مسائل دیده می‌شود.

## ساختار کد

```
src/
  pages/            صفحات (HTML) — در فاز ۳ به Page Layout / صفحات شیرپوینت تبدیل می‌شوند
  partials/         هدر، فوتر، نوار بالا، لایه‌ها — در فاز ۳ به shastan.master تبدیل می‌شوند
  styles/main.css   Tailwind + کامپوننت‌ها (shn-*)
  js/
    config.js       نام لیست‌ها، آدرس صفحات، تشخیص حالت (mock / sp)
    schema.js       تعریف همه‌ی انواع محتوا و فیلدها (منبع واحد فرم‌ها، کارت‌ها، کارتابل و اسکریپت ساخت لیست‌ها)
    core/           util (escape خودکار)، format (تاریخ شمسی)، jalali (تبدیل تقویم)
    data/
      repository.js   تنها نقطه‌ی دسترسی صفحات به داده
      mock-provider.js  پیاده‌سازی نمایشی — رفتار Content Approval را شبیه‌سازی می‌کند
      sp-provider.js    پیاده‌سازی SharePoint 2019 (REST برای خواندن، JSOM برای نوشتن)
    ui/             کامپوننت‌ها، فرم‌ساز + تاریخ‌نگار شمسی + کپچا، مودال/پیام، هدر و منو
    pages/          منطق هر صفحه
sharepoint/layouts/Shastan/login.aspx   صفحه‌ی ورود FBA
```

## تصمیم‌های فنی مهم

- **Tailwind کامپایل‌شده** با پیشوند `tw-`، بدون preflight، و `important: '#shastan-app'` تا با CSS شیرپوینت (`corev15.css`، ریبون، AspMenu) تداخل نداشته باشد و بر آن غلبه کند. ریست‌های پایه با `:where()` بی‌اثر روی specificity نوشته شده‌اند.
- **بدون CDN**: فونت دانا (woff2 + woff، وزن ۴۰۰ و ۷۰۰)، FontAwesome و همه‌ی فایل‌ها محلی هستند.
- **امنیت XSS**: همه‌ی HTML با تابع `html\`\`` ساخته می‌شود که مقادیر را خودکار escape می‌کند؛ لینک‌های واردشده توسط کاربر فقط `http/https/mailto` مجازند؛ متن‌های چندخطی به‌صورت متن ساده ذخیره و امن به پاراگراف تبدیل می‌شوند.
- **تاریخ شمسی** در نمایش (`Intl` با تقویم persian) و در ورود (انتخابگر تاریخ شمسی اختصاصی)؛ ذخیره به‌صورت ISO ظهر همان روز تا جابجایی منطقه‌ی زمانی روز را عوض نکند.
- **نقش کاربر در شیرپوینت از مجوز مؤثر** تشخیص داده می‌شود (ApproveItems → هلدینگ، EditListItems روی آیتم شرکت → کاربر همان شرکت)، چون عضویت از طریق گروه AD در `/currentuser/groups` دیده نمی‌شود.
- **UI امنیت نیست**: همه‌ی محدودیت‌ها در شیرپوینت با Content Approval، Draft Item Security و پوشه‌ی هر شرکت اعمال می‌شوند؛ حالت نمایشی همین قواعد را شبیه‌سازی می‌کند.
- دسترس‌پذیری: لینک پرش به محتوا، برچسب همه‌ی فیلدها، `aria-*` برای منو، تب، مودال و پیام‌ها، کنترل با صفحه‌کلید (Esc، جهت‌ها در تب‌ها، `/` برای جستجو)، `prefers-reduced-motion`.

## تست‌شده

- همه‌ی ۲۵ نمای صفحات در سه نقش، در عرض دسکتاپ (۱۳۶۶) و موبایل (۳۹۰): بدون خطای Console و بدون اسکرول افقی.
- سناریوی کامل ثبت → برگشت → اصلاح → تأیید → انتشار عمومی.
- جداسازی شرکت‌ها (شرکت دیگر به پیش‌نویس دسترسی ندارد)، کپچای نادرست، پنهان بودن نماینده برای کاربر ناشناس.

## محدودیت‌ها و کار باقی‌مانده

- `sp-provider.js` و `login.aspx` روی فارم واقعی اجرا نشده‌اند و در فاز ۳ روی محیط تست شیرپوینت باید تست شوند.
- هندلر `PublicSubmit.ashx` و `Captcha.ashx` (سمت سرور) در فاز ۶ ساخته می‌شوند؛ قرارداد آن‌ها:
  - `GET Captcha.ashx` → `{ "token": "...", "image": "data:image/png;base64,..." }`
  - `POST PublicSubmit.ashx` (multipart: `kind=proposal|contact`، فیلدهای فرم، `CaptchaToken`، `CaptchaAnswer`، `files`) → `{ "ok": true, "trackingCode": "P-1405-0012" }` یا `{ "ok": false, "message": "...", "field": "CaptchaAnswer" }`
- نقشه‌ی صفحه‌ی تماس جای‌نگهدار است (تصویر یا سرویس نقشه‌ی داخلی).
